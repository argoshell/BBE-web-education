# beer_web — Plan

Port Randall Beer's *EvolutionaryAgents* C++ code (v1.2, https://rdbeer.pages.iu.edu/)
to an interactive website for exploring evolved CTRNN agents. Start with the
one-legged walker, but design so other agents/tasks plug in (next: the visual
categorizer from `VisualAgent.cpp`, Beer 2003).

## Decisions (from planning Q&A, 2026-10-20)

| Topic | Decision |
|---|---|
| Port strategy | **Both**: hand-written TypeScript port for the app + original C++ compiled to WASM/native as a reference, compared in tests/CI |
| Frontend | Vite + React + TypeScript |
| Hosting | GitHub Pages, deployed by GitHub Actions from `main` |
| Original C++ | **Not committed** (no license). `scripts/fetch-beer-sources.mjs` downloads it into gitignored `reference/` |
| WASM toolchain | emsdk installed locally (Windows); same version pinned in CI |
| Repo | Public GitHub repo created via `gh` |
| Walker variants (v1) | 5-neuron CPG (`Step`, default = `cpg.ns`), 2-neuron (`Step2`), 1-neuron w/ angle sensor (`Step1`), general CTRNN + leg-angle sensor (new), `PerfectStep` baseline |
| Phase portrait | Trajectories in any 2 chosen state variables + vector field & nullclines when 2 neurons are chosen (others frozen at the current value) |
| Lineage | All four: ancestor chain of best, best-per-generation, full population explorer, side-by-side diff |
| Next agent | Visual categorizer |

## Notes from reading the original source

- `random.cpp` is Numerical Recipes `ran1` + Knuth polar Gaussians. It uses only
  32-bit-safe integer arithmetic (Schrage), so the TS port can be **bit-identical**.
- `Math.exp`/`atan2` may differ from libm in the last ulp, so long chaotic runs can
  drift. Tests compare against C++ traces with tolerances (step-wise ~1e-9 early
  on; summary stats such as average velocity ~1e-6).
- `Pi = 3.1415926` (truncated). Keep it in the port for fidelity.
- **`cpg.ns` has no size header**, but `operator>>(istream, CTRNN&)` reads one first.
  The TS loader accepts both formats and infers N from the value count (N=5 → 40 values).
  The reference harness prepends the size.
- `TSearch` GA crossover calls the *global* `ProbabilisticChoice` rather than the
  search's `rs`, so GA runs aren't fully seed-determined. Reproduce it in the
  reference build; the TS port uses `rs` (flagged as a documented deviation).
- `TSearch` doesn't record parentage. The TS port adds parent IDs (1 for mutation,
  2 for crossover), so lineage is a DAG and becomes a tree with mutation only.
- Hill-climbing mode keeps the parent if the child is worse, so "same individual,
  next generation" also needs representing (an identity edge, no new ID).

## Architecture

Single Vite package (no monorepo until it hurts):

```
src/
  sim/
    core/            # agent-agnostic, no DOM
      random.ts      # RandomState (ran1, Gaussian), bit-exact port
      ctrnn.ts       # CTRNN: Euler/RK4, state, sigmoid, (de)serialize .ns
      tsearch.ts     # TSearch port + lineage recording
      genome.ts      # [-1,1] genotype <-> phenotype mapping helpers
      agent.ts       # AgentModule interface (below)
    agents/
      legged/        # LeggedAgent body, controller variants, evaluate(), presets (cpg.ns)
      visual/        # (phase 4)
  workers/
    evolve.worker.ts # evaluates individuals; pool sized to hardwareConcurrency
  ui/
    components/      # TracePlot, PhasePortrait, ParamPanel, TimeScrubber, LineageView, ...
    pages/           # per-agent pages assembled from generic components + agent's BodyView
native/
  CMakeLists.txt     # builds original C++ (from reference/) natively and via emscripten
  harness/           # small mains that dump traces as JSON for regression fixtures
scripts/
  fetch-beer-sources.mjs
tests/
  fixtures/          # committed traces generated by the C++ harness (outputs, not source)
reference/           # gitignored — original C++
```

### AgentModule interface (the generalization point)

```ts
interface AgentModule<Params> {
  id: string; name: string; citation: string;
  paramSchema: ParamSpec[];          // name, group, range, step → drives ParamPanel sliders
  presets: Record<string, Params>;   // e.g. "Beer cpg.ns"
  genome: { size(cfg): number; decode(g: Float64Array, cfg): Params; encode(p): Float64Array };
  simulate(p: Params, opts: { duration, dt, seed }): Recording;   // named channels over time
  evaluate(p: Params, rs: RandomState): number;                   // fitness, worker-safe
  channels: ChannelSpec[];           // e.g. o1..oN, y1..yN, legAngle, footState, cx, vx
  BodyView: React.FC<{ rec: Recording; t: number }>;              // only per-agent UI
}
```

Trace plots, phase portraits, parameter panels, evolution and lineage views are
generic over `Recording` channels and `paramSchema`. A new agent only supplies
physics, an evaluation function and a body renderer.

## UI (walker page)

- **Body view**: canvas animation of the body, leg and foot (stance/swing coloring), with a
  scrolling ground and a velocity readout.
- **Neural traces**: uPlot stacked traces of neuron outputs, plus leg angle, foot state and
  forward/backward force. Stance and swing shaded.
- **Phase portrait**: choose X/Y channels. Trajectory colored by time or by stance/swing. For
  neuron×neuron, a vector field and nullclines (marching squares on a grid) with the other
  neurons and inputs frozen at the scrubbed time.
- **Shared time cursor**: scrubbing or playing moves all three views together.
- **Parameter panel**: τ, θ, gain, weight matrix (heatmap editor), sensor weights,
  body constants (MaxLegForce, angle limits, …), dt, duration, initial-state seed.
  Each change triggers a rerun (2000 steps is sub-millisecond), so sliders update live.
  State is encoded in the URL so configurations can be shared.
- **Evolution panel**: population, generations, mutation variance, selection/reproduction
  mode, elitism, crossover, seed. Runs in workers with live fitness curve, pause and resume.
- **Lineage**: best/mean fitness per generation (click → load that best); ancestor chain
  of the final best (click → load); population explorer (generation × fitness scatter,
  optional PCA of genomes); pin up to N individuals to overlay traces, phase plots and gaits,
  with a parameter-diff heatmap. Runs are saved to IndexedDB and can be exported/imported as JSON.

## Phases

0. **Scaffold**: git, Vite/React/TS, ESLint/Prettier, Vitest, fetch script, emsdk build
   of the reference C++, trace harness, GitHub repo, Actions (test + Pages deploy).
1. **Core port**: RandomState (bit-exact test), CTRNN, LeggedAgent (all variants plus
   angle sensor). Regression tests against C++ traces, including `cpg.ns` average velocity.
2. **Walker explorer**: body view, traces, phase portrait with nullclines, parameter panel,
   linked time cursor, URL state. Optional "run the WASM reference" toggle to diff live.
3. **Evolution and lineage**: TSearch port with parent tracking, worker pool, the four
   lineage views, saved runs.
4. **Generalize**: implement the visual categorizer against `AgentModule` and
   refactor anything walker-specific that leaks.
5. **Analysis extras**: equilibrium points and their movement with leg angle (Beer's
   stance/swing "dynamical module" analysis), more agents.
